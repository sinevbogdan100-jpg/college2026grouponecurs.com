Автоматическая доставка уведомлений SBP GROUP
============================================

Сайт уже показывает индикаторы поддержки, умеет воспроизводить звук и запрашивать
разрешение на системные уведомления. Пока сервер не развёрнут, системные уведомления
работают только при открытом сайте; этот статус явно указан в настройках.

Для доставки при закрытом сайте подготовлены Firebase Functions: регистрация
подписок браузеров, отправка новых объявлений и адресная отправка ответов поддержки.
Секретный ключ никогда не передаётся сайту и не хранится в GitHub.

Настройка один раз, из корня репозитория:

1. Войти в Firebase CLI под владельцем проекта sbpgroup-toe-26-9-1:
   `firebase login`. Для Cloud Functions проект должен поддерживать развёртывание
   функций (план Blaze). Если подключение плана требует оплаты, владелец делает это
   самостоятельно. Firestore должен быть в Native mode.
2. Установить серверные зависимости: `npm ci --prefix functions`.
3. Сгенерировать ключи: `node functions/generate-vapid.cjs https://АДРЕС-САЙТА`.
   Использовать реальный публичный HTTPS адрес сайта. Ключи генерировать один раз.
4. Импортировать приватный ключ в Secret Manager:
   `firebase functions:secrets:set VAPID_PRIVATE_KEY --data-file functions/vapid-private.txt --project sbpgroup-toe-26-9-1`.
5. Развернуть только эти функции:
   `firebase deploy --only functions:sbp-group-push --project sbpgroup-toe-26-9-1`.
   Публичный ключ и контактный адрес берутся из созданного локального .env файла.
   Этот шаг не заменяет действующие Firestore Rules и не меняет хостинг сайта.
6. Обновить сайт, открыть Настройки → Уведомления → Разрешить уведомления.
   Статус должен стать «Включены, в том числе при закрытом сайте» только после
   успешной регистрации подписки на сервере. Если разрешение уже включено, достаточно
   перезагрузить страницу; сайт подключит серверную доставку автоматически.

Проверка на двух устройствах:

- Пользователь отправляет обращение, владелец отвечает именно на него. Пользователь
  видит красный индикатор и слышит звук, если включил звук и взаимодействовал с сайтом.
- Пользователь закрывает все вкладки сайта. Новый ответ должен появиться в системных
  уведомлениях; нажатие открывает поддержку. Владелец публикует новое объявление —
  подписанные устройства получают уведомление центра событий.
- Ответы другого пользователя не приходят. После отзыва права support администратор
  не получает новые обращения. Выключение уведомлений удаляет подписку устройства.
- Исторические сообщения при загрузке не воспроизводят звук. Повторный серверный
  триггер не создаёт новую доставку уже отправленного события.

На iPhone/iPad с поддержкой Web Push сайт необходимо добавить на экран «Домой» и
открыть как приложение; разрешение запрашивается только нажатием кнопки пользователя.
Звук внутри сайта — мягкий двухтонный сигнал. Звук системных уведомлений выбирает ОС.
Service Worker не кэширует страницы и не мешает получать новые версии сайта.

Коллекции toe_push_devices и вложенные deliveries доступны только серверному Admin
SDK. Действующие правила не разрешают клиентам читать эти коллекции. Endpoint и
ключи подписки не выводятся в публичные ответы. Сервер выбирает получателя личного
ответа по UID в имени диалога, а не по изменяемому полю ownerUid.

После настройки можно добавить Firestore TTL для поля expiresAt в collection group
deliveries, чтобы очищать отметки доставки. Сохраните приватный VAPID ключ в защищённом
хранилище: его замена потребует переподписки устройств.
